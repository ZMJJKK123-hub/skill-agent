# Forge Agent — Skill 与 Tool 需求明细表

> **版本**: v2.0 | **日期**: 2026-08-04 | **加载器**: Forge (MC 26.2 → Forge 65.1.0)  
> **定位**: 按元素类型逐个拆解——Agent 生成每种东西需要创建哪些文件、依赖哪些Skill文档、调用哪些Tool函数。  
> **注意**: Forge 与 NeoForge 高度相似，本文档标注了 **与NeoForge的差异点**。公共部分沿用NeoForge文档。

## Forge vs NeoForge 快速差异概览

| 差异点 | **Forge (65.x)** | **NeoForge (26.2.x)** |
|--------|-----------------|----------------------|
| **包名** | `net.minecraftforge.*` | `net.neoforged.*` |
| **元数据文件** | `mods.toml` | `neoforge.mods.toml` |
| **Gradle插件** | `net.minecraftforge.gradle` (Mojang Mappings) | `net.neoforged.gradle.userdev` |
| **Mixin** | 需手动配置MixinGradle | 内置Mixin支持 |
| **网络Payload** | `SimpleChannel` 传统API | `CustomPacketPayload` + `PayloadRegistrar`（新） |
| **Capability系统** | Capability API 保留 | 正在向Data Component迁移 |
| **DataGen** | `GatherDataEvent` 基本一致 | 一致 |
| **BlockEntity** | `BlockEntity`（一致） | 一致 |
| **事件总线** | `@Mod.EventBusSubscriber` + `IEventBus` | 换成 `IEventBus`（用法一致） |
| **Maven仓库** | `maven.minecraftforge.net` | `maven.neoforged.net` |
| **Registry** | `DeferredRegister`（一致） | 一致 |
| **MC 26.2推荐版本** | **65.1.0** (recommended) | 26.2.0.45-beta |

> **关键结论**: Forge 65.x 和 NeoForge 在 **95%的API上是相同的**。对Agent来说，主要区别是包名、元数据文件名、Gradle插件、网络API。Agent可以通过一个**加载器切换Skill**来处理这些差异。

## 0. 全局基础：Forge与NeoForge的差异处理

### 0.1 Forge版全局文件

与NeoForge一致，但有以下关键差异：

| 文件 | Forge区别 |
|------|----------|
| `build.gradle` | 使用 `net.minecraftforge.gradle` 插件，配置略有不同 |
| `settings.gradle` | Maven仓库换成 `maven.minecraftforge.net` |
| `gradle.properties` | `forge_version=65.1.0` |
| `META-INF/` | **`mods.toml`**（不是 `neoforge.mods.toml`） |
| `pack.mcmeta` | 一致 |
| `Mod主类` | 包名 `net.minecraftforge.fml.common.Mod` |

### 0.2 Forge build.gradle 关键差异

```groovy
plugins {
    id 'java-library'
    id 'eclipse'
    id 'idea'
    id 'maven-publish'
    id 'net.minecraftforge.gradle' version '[6.0,6.2)'  // 注意：不同于NeoForge的userdev插件
}

// Forge使用Mojang Mappings
minecraft {
    mappings channel: 'official', version: "${minecraft_version}"  // 或 parchment
    // 或使用Parchment:
    // mappings channel: 'parchment', version: "2024.xx.xx-${minecraft_version}"
}

dependencies {
    minecraft "net.minecraftforge:forge:${minecraft_version}-${forge_version}"
    // 注意: Forge 用 "minecraft" 配置，NeoForge 用 "implementation"
}

// runs 配置略有不同
runs {
    client {
        workingDirectory project.file('run')
        property 'forge.logging.markers', 'REGISTRIES'
        property 'forge.logging.console.level', 'debug'
        mods {
            "${mod_id}" {
                source sourceSets.main
            }
        }
    }
    server {
        workingDirectory project.file('run')
        property 'forge.logging.markers', 'REGISTRIES'
        property 'forge.logging.console.level', 'debug'
        mods {
            "${mod_id}" {
                source sourceSets.main
            }
        }
    }
    data {
        workingDirectory project.file('run')
        property 'forge.logging.markers', 'REGISTRIES'
        property 'forge.logging.console.level', 'debug'
        args '--mod', mod_id, '--all',
             '--output', file('src/generated/resources/'),
             '--existing', file('src/main/resources/')
        mods {
            "${mod_id}" {
                source sourceSets.main
            }
        }
    }
}
```

> **Skill必需**: `gradle-config-guide-forge.md` — **新建**：Forge专用Gradle配置（不同于NeoForge）。

### 0.3 Forge mods.toml

```toml
modLoader = "javafml"
loaderVersion = "[65,)"
license = "MIT"

[[mods]]
modId = "my_mod"
version = "${file.jarVersion}"
displayName = "My Mod"
description = "A mod generated by AI agent."

[[dependencies.my_mod]]
    modId = "forge"
    mandatory = true
    versionRange = "[65,)"
    ordering = "NONE"
    side = "BOTH"
[[dependencies.my_mod]]
    modId = "minecraft"
    mandatory = true
    versionRange = "[26.2,)"
    ordering = "NONE"
    side = "BOTH"
```

> **格式差异**: NeoForge使用 `[[mods.dependencies.xxx]]`（嵌套），Forge使用 `[[dependencies.xxx]]`（平级）。且Forge用 `mandatory`，NeoForge用 `type="required"`。

### 0.4 Forge Mod主类

```java
package com.example.my_mod;

import net.minecraftforge.fml.common.Mod;  // 注意包名！
import net.minecraftforge.common.MinecraftForge;
import net.minecraftforge.fml.javafmlmod.FMLJavaModLoadingContext;
import org.slf4j.Logger;
import com.mojang.logging.LogUtils;

@Mod(MyMod.MODID)
public class MyMod {
    public static final String MODID = "my_mod";
    private static final Logger LOGGER = LogUtils.getLogger();

    public MyMod() {  // Forge使用无参构造器，通过FMLJavaModLoadingContext获取事件总线
        var modEventBus = FMLJavaModLoadingContext.get().getModEventBus();

        ModBlocks.BLOCKS.register(modEventBus);
        ModItems.ITEMS.register(modEventBus);
        ModBlockEntities.BLOCK_ENTITIES.register(modEventBus);
        ModCreativeTabs.CREATIVE_MODE_TABS.register(modEventBus);

        modEventBus.addListener(ModEventSubscriber::onCommonSetup);
        modEventBus.addListener(ModEventSubscriber::onClientSetup);

        // Forge 网络注册（不同于NeoForge）
        ModNetworking.register();

        MinecraftForge.EVENT_BUS.register(new ModEvents()); // Forge需要手动注册事件总线
        MinecraftForge.EVENT_BUS.register(this);
    }
}
```

> **关键差异**: Forge使用 `FMLJavaModLoadingContext.get().getModEventBus()` 获取事件总线，而NeoForge通过构造器注入 `IEventBus modEventBus`。

### 6.1 Forge网络同步（传统SimpleChannel）

```java
// Forge网络通道注册
public class ModNetworking {
    private static final String PROTOCOL_VERSION = "1";
    public static final SimpleChannel CHANNEL = ChannelBuilder.named(
            ResourceLocation.fromNamespaceAndPath(MODID, "main"))
        .serverAcceptedVersions((s, v) -> true)
        .clientAcceptedVersions((s, v) -> true)
        .networkProtocolVersion(1)
        .simpleChannel();

    public static void register() {
        CHANNEL.messageBuilder(SyncProgressPacket.class, 0, NetworkDirection.PLAY_TO_CLIENT)
            .encoder(SyncProgressPacket::encode)
            .decoder(SyncProgressPacket::decode)
            .consumerMainThread(SyncProgressPacket::handle)
            .add();
    }
}
```

> **Skill必需**: `networking-guide-forge.md` — Forge SimpleChannel网络API（不同于NeoForge的Payload系统）。

## 10. Forge特有能力系统 (Capability)

这是 **Forge独有的**（NeoForge正在淘汰Capability，迁移到Data Component）。

### 10.1 Capability用途

Capability用于给任意对象（Entity、BlockEntity、ItemStack、Level等）附加自定义数据和行为，而无需修改原版类。

例如："给玩家附加上'魔力值'数据" 或 "让方块有能量存储"

### 10.2 Capability注册

```java
// 定义能力接口
public interface IManaStorage {
    int getMana();
    int getMaxMana();
    void setMana(int mana);
}

// 注册
public static final Capability<IManaStorage> MANA = CapabilityManager.get(
    new CapabilityToken<>(){}
);

// 给实体附着
@SubscribeEvent
public static void onAttachCapabilities(AttachCapabilitiesEvent<Entity> event) {
    if (event.getObject() instanceof Player) {
        event.addCapability(
            ResourceLocation.fromNamespaceAndPath(MODID, "mana"),
            new ManaProvider()
        );
    }
}
```

> **Skill必需**: `capability-guide-forge.md` — **新建**：Capability系统完整指南（Forge特有，NeoForge无）。

| `generate_capability_provider` | 生成ICapabilityProvider |

## 11. Forge网络系统 (SimpleChannel)

Forge使用传统的 `SimpleChannel`，不同于NeoForge 26.x的 `Payload` 系统。

### 11.1 SimpleChannel 数据包示例

```java
// 数据包定义（传统方式）
public class SyncManaPacket {
    private final int mana;

    public SyncManaPacket(int mana) { this.mana = mana; }

    public static void encode(SyncManaPacket msg, FriendlyByteBuf buf) {
        buf.writeVarInt(msg.mana);
    }
    public static SyncManaPacket decode(FriendlyByteBuf buf) {
        return new SyncManaPacket(buf.readVarInt());
    }
    public static void handle(SyncManaPacket msg, CustomPacketPayload.Context ctx) {
        ctx.enqueueWork(() -> {
            // 客户端处理
            ClientManaData.set(msg.mana);
        });
    }
}
```

> **Skill必需**: `networking-guide-forge.md` — **新建**：SimpleChannel完整API指南。

### 11.2 Forge网络需要的 Tool

| Tool | 说明 |
|------|------|
| `generate_forge_packet_class` | 生成Forge SimpleChannel数据包（encode/decode/handle） |
| `generate_forge_network_registration` | 生成SimpleChannel注册代码 |

## 13. Tool接口完整清单（Forge版）

### 与NeoForge的Tool差异

绝大多数Tool是相同的，只需支持 `loader=forge` 参数来切换：
- 包名生成（`net.neoforged.*` → `net.minecraftforge.*`）
- Registry常量名（`Registries.BLOCK` → `ForgeRegistries.BLOCKS`）
- 元数据文件名（`neoforge.mods.toml` → `mods.toml`）
- Gradle配置内容
- 网络代码风格（SimpleChannel vs Payload）

### Forge独有的Tool

| Tool | 说明 |
|------|------|
| `generate_capability_interface` | Forge Capability接口 |
| `generate_capability_provider` | ICapabilityProvider |
| `generate_capability_attachment` | AttachCapabilitiesEvent处理 |
| `generate_forge_packet_class` | Forge SimpleChannel数据包 |
| `generate_forge_network_registration` | SimpleChannel注册 |
| `forge_to_neoforge_migrator` | 将Forge代码自动转为NeoForge代码（包名+API替换） |

### 删除的Tool（NeoForge独有，Forge不需要）

- `generate_particle_definition_json` — Forge不使用particles JSON（Forge 65.x 可能还不支持MC 26.x的粒子JSON新格式，需验证）
