## 最低测试覆盖率：80%

测试类型（全部必需）：
1. **单元测试** — 单个函数、工具、组件
2. **集成测试** — API 端点、数据库操作
3. **E2E 测试** — 关键用户流程

## 测试驱动开发（TDD）

强制工作流：
1. 写测试（RED）— 先写失败测试，明确需求
2. 运行测试 — 应该失败，确认测试有效
3. 写最小实现（GREEN）— 刚好让测试通过，不多做
4. 运行测试 — 应该全部通过
5. 重构（IMPROVE）— 改善代码质量，保持测试通过
6. 验证覆盖率（80%+）— 不达标则补测试

## 测试文件组织

- 测试文件与源文件同目录，命名 `test_*.py` 或 `*.test.js`
- 每个公共函数至少 3 个测试用例：正常、边界、异常
- Mock 外部依赖（网络、文件系统、数据库）

## 命名规范

- 测试函数名：`test_应当_行为_当_条件`
- 例：`test_应当_返回404_当_用户不存在`

## 断言原则

- 每个测试只断言一个行为
- 断言信息要清晰，失败时能快速定位
- 禁止用 `assertTrue(x)`，用 `assertEqual(x, expected)` 带上下文
