环境属性（Environment attribute）是根据不同环境来控制各种视觉效果和游戏机制等玩法的机制。

# 环境属性

环境属性提供了基于不同环境而具有不同游戏玩法和视觉效果的机制。所谓“环境”，即环境属性源（Environment Attribute Source），目前游戏共有四个环境属性源，按照应用顺序依次为维度、生物群系、时间线和天气。

维度和天气提供了全局的环境属性，时间线提供了基于时间的环境属性，生物群系提供了基于特定位置的环境属性。

## 修饰符

不同的环境属性源可能提供相同的环境属性，游戏会将其叠加操作后作为实际应用的环境属性，而修饰符（Modifiers）决定了叠加操作的方式。

修饰符的可用值取决于具体的环境属性，所有的环境属性均具有覆盖操作（
```
override
```

）这一种修饰符，其效果为仅应用最后一个应用的环境属性。

例如：若主世界维度指定天空颜色为蓝色，平原生物群系指定天空颜色为绿色，其他主世界生物群系未定义天空颜色，则玩家在主世界的平原生物群系时，天空颜色为绿色；在主世界的其他生物群系时，天空颜色为蓝色。

## 插值

部分环境属性可插值，当玩家在环境属性不同的区域间移动时，游戏不会立刻切换环境效果，而是会对其进行平滑过渡。游戏会在插值计算时一并应用修饰符。

环境属性的可插值是其固有性质，游戏并不总是进行插值计算。目前游戏会在下列情况下使用插值：

- 计算部分以摄像机坐标获取的环境属性。在摄像机周围半径10格内占据区域最多的生物群系会对插值产生最大的影响。
- 计算时间线的环境属性轨道。根据属性轨道和时间进行插值。

例如：若主世界维度指定云层高度为100，平原生物群系指定云层高度为1700，其他主世界生物群系未定义云层高度，则摄像机在主世界的平原生物群系与其他生物群系的交界处时云层高度可以是100至1700之间的任何值，但对于快乐恶魂而言云层高度只有100和1700两个值。

## 技术细节

游戏中存在3个相互独立的环境属性系统：

- 服务端世界环境属性：上述介绍的平凡的环境属性系统，具有维度、生物群系、时间线、天气四个环境属性源。
- 客户端世界环境属性：具有维度、生物群系、时间线、天气四个环境属性源。在此基础上： - 当选项“隐藏天空闪烁效果”为关时，如果产生了闪电，则在2游戏刻内： - 环境属性 ``` visual/sky_color ``` ：以初始值为插值起点，以 #CCF0FF为插值终点进行线性插值，插值因子为0.22，即(r,g,b)=(r+0.22×(204−r),g+0.22×(240−g),b+0.22×(255−b))。 - 环境属性 ``` visual/sky_light_factor ``` ：修改为 ``` 1.0 ``` 。
- 尚未生成完毕的区块中的环境属性：Java版26.3前，始终为空；Java版26.3起，只有维度和生物群系两个环境属性源。

- 环境属性轨道：环境属性轨道可以定义在时间线定义文件内，定义了环境属性随时间变化的值，格式详见时间线定义格式 § 定义格式。

# 通用结构

以下为被不同环境属性和环境属性修饰符使用的较为复杂的数据类型。

## RGB颜色

- [图:字符串][图:整型][图:NBT列表/JSON数组] RGB颜色

- - - 若为[图:字符串]字符串，则以十六进制RGB字符串 ``` #rrggbb ``` 表示RGB颜色，每个通道占用2个字符，依次为红色通道、绿色通道、蓝色通道。 - 最大值为 ``` #FFFFFF ``` ，且除 ``` # ``` 前缀外字符串必须有6个字符，不区分大小写。游戏在反序列化为整数时始终认为最高8位为255，序列化时始终认为最高8位为0。 - - 若为[图:整型]整型，则以十进制数字表示RGB颜色，每个通道占用8位。除最高8位外，从高到低依次为红色通道、绿色通道、蓝色通道。 - 即：Red<<16 + Green<<8 + Blue，最高8位对RGB颜色没有任何作用。 - - 若为[图:NBT列表/JSON数组]列表，则以3个浮点数表示RGB颜色，依次代表红色通道、绿色通道、蓝色通道。游戏在保存为整数时始终认为最高8位为255。 - [图:单精度浮点数]：颜色的R通道分量。取值为 ``` [0, 1] ``` 的闭区间。 - [图:单精度浮点数]：颜色的G通道分量。取值为 ``` [0, 1] ``` 的闭区间。 - [图:单精度浮点数]：颜色的B通道分量。取值为 ``` [0, 1] ``` 的闭区间。

## ARGB颜色

- [图:字符串][图:整型][图:NBT列表/JSON数组] ARGB颜色

- - - 若为[图:字符串]字符串，则以十六进制ARGB字符串 ``` #aarrggbb ``` 表示ARGB颜色，每个通道占用2个字符，依次为透明通道、红色通道、绿色通道、蓝色通道。 - 最大值为 ``` #FFFFFFFF ``` ，且除 ``` # ``` 前缀外字符串必须有8个字符，不区分大小写。 - - 若为[图:整型]整型，则以十进制数字表示ARGB颜色，每个通道占用8位。从高到低依次为透明通道、红色通道、绿色通道、蓝色通道。 - 即：Alpha<<24 + Red<<16 + Green<<8 + Blue。 - - 若为[图:NBT列表/JSON数组]列表，则以4个浮点数表示ARGB颜色，依次代表红色通道、绿色通道、蓝色通道、透明通道。 - [图:单精度浮点数]：颜色的R通道分量。取值为 ``` [0, 1] ``` 的闭区间。 - [图:单精度浮点数]：颜色的G通道分量。取值为 ``` [0, 1] ``` 的闭区间。 - [图:单精度浮点数]：颜色的B通道分量。取值为 ``` [0, 1] ``` 的闭区间。 - [图:单精度浮点数]：颜色的A通道分量。取值为 ``` [0, 1] ``` 的闭区间。

# 环境属性列表

## 视觉效果

这些环境属性主要影响游戏的视觉效果。

### visual/fog_color

控制迷雾的颜色。迷雾的最终颜色也会被昼夜更替、药水效果等因素影响。

数据类型为RGB颜色，默认值为
 #000000，可使用RGB颜色修饰符。可插值，获取位置为摄像机的位置。

### visual/fog_start_distance

控制迷雾的起始距离，以方块为单位。迷雾的起始距离是迷雾从完全透明到开始有影响的距离，如果为负数，则迷雾将初始存在，就像它从摄像机后面开始产生影响一样。迷雾的最终起始距离也会受天气等因素影响。

数据类型为[图:单精度浮点数]浮点数，默认值为
```
0.0
```

，可使用浮点修饰符。可插值，获取位置为摄像机的位置。

### visual/fog_end_distance

控制迷雾的结束距离，以方块为单位。迷雾的结束距离也被称为可见距离，是迷雾达到最大浓度的距离，超过结束距离后迷雾将完全不透明。迷雾的最终结束距离也会受天气等因素影响，且不会小于96格。

数据类型为[图:单精度浮点数]浮点数，且必须大于0，默认值为
```
1024.0
```

，可使用浮点修饰符。可插值，获取位置为摄像机的位置。

### visual/sky_fog_end_distance

控制天空迷雾的结束距离，以方块为单位。

数据类型为[图:单精度浮点数]浮点数，且必须大于0，默认值为
```
512.0
```

，可使用浮点修饰符。可插值，获取位置为摄像机的位置。

### visual/cloud_fog_end_distance

控制云层迷雾的结束距离，以方块为单位。

数据类型为[图:单精度浮点数]浮点数，且必须大于0，默认值为

```
2048.0
```

，可使用浮点修饰符。可插值，获取位置为摄像机的位置。

### visual/water_fog_color

控制水下迷雾的颜色。水下迷雾的最终颜色也会被昼夜更替、药水效果等因素影响。

数据类型为RGB颜色，默认值为
 #050533，可使用RGB颜色修饰符。可插值，获取位置为摄像机的位置。

### visual/water_fog_start_distance

控制水下迷雾的起始距离，以方块为单位。如果为负数，则迷雾将初始存在，就像它从摄像机后面开始产生影响一样。

数据类型为[图:单精度浮点数]浮点数，默认值为

```
-8.0
```

，可使用浮点修饰符。可插值，获取位置为摄像机的位置。

### visual/water_fog_end_distance

控制水下迷雾的结束距离，以方块为单位。水下迷雾的最终结束距离也和玩家在水下的时长有关。

数据类型为[图:单精度浮点数]浮点数，且必须大于0，默认值为
```
96.0
```

，可使用浮点修饰符。可插值，获取位置为摄像机的位置。

### visual/sky_color

控制天空颜色。

数据类型为RGB颜色，默认值为

### visual/sunrise_sunset_color

控制日出日落效果颜色。如果完全透明则不会渲染日出日落效果。日出日落效果仅在
```
overworld
```

天空盒下才会渲染，在天空东侧还是西侧渲染取决于太阳的位置。

数据类型为ARGB颜色，默认值为
 #00000000，可使用ARGB颜色修饰符。可插值，获取位置为摄像机的位置。

### visual/cloud_color

控制云层颜色。如果完全透明则不会渲染云，且实体也不会认为自身在云中，例如快乐恶魂对云层的判定。

数据类型为ARGB颜色，默认值为

### visual/cloud_height

控制云层高度。如果云层透明度不为0，则实体在世界界限内、云层高度至云层高度之上4格内的区域时会认为自身在云中。

数据类型为[图:单精度浮点数]浮点数，默认值为
```

```

### visual/sun_angle

控制太阳的高度角，单位为度，为0时恰好在摄像机正上方，从东到西顺时针计算。太阳仅在
```

```

天空盒下才会渲染。它也影响时钟的角度和阳光探测器的部分计算。

数据类型为[图:单精度浮点数]浮点数，默认值为
```
0.0
```

- 天空中的太阳渲染：摄像机位置。

- 阳光探测器：阳光探测器的位置。

当初始值和目标值之差对360.0取余超过90.0时，游戏直接跳到目标值，不进行插值。

## 声音效果

### audio/background_music


（音乐）分类，始终跟随玩家播放。若开启了显示音乐弹窗选项，则游戏会将声音资源文件路径的
```

```

数据类型较复杂（见下），默认为空对象，仅接受
```

```

修饰符。不可插值，获取位置为摄像机的位置。

- [图:NBT复合标签/JSON对象] - [图:NBT复合标签/JSON对象]default：默认音乐。如果此值不存在，则不会播放音乐。 - [图:字符串][图:NBT复合标签/JSON对象]*sound：要播放的音乐。 - - 声音事件，见Template:Nbt inherit/sound event/source - [图:整型]*min_delay：两次播放间最小延迟。会受到音乐播放频率选项的限制，因此实际最小延迟不会超过24000游戏刻（20分）。 - [图:整型]*max_delay：两次播放间最大延迟。会受到音乐播放频率选项的限制，因此实际最大延迟不会超过24000游戏刻（20分）。 - [图:布尔型]*replace_current_music：是否立即替换正在播放的音乐。 - [图:NBT复合标签/JSON对象]underwater：如果存在，则玩家在水下时会播放此音乐。 - 格式同[图:NBT复合标签/JSON对象]default。 - [图:NBT复合标签/JSON对象]creative：如果存在，则玩家在创造模式时会播放此音乐。 - 格式同[图:NBT复合标签/JSON对象]default。

### audio/ambient_sounds

控制环境音效。环境音效包括三类声音：分别是循环音效、附加音效和氛围音效。三种音效会互相独立地计算播放条件与播放声音，声音分类都归属
```
ambient
```

（环境）分类。

- 循环音效会在玩家处于生物群系中时立刻播放，循环播放。声音始终跟随玩家播放，且音量会在玩家进出生物群系时淡入淡出。
- 附加音效会在玩家处于此生物群系时每刻随机播放。声音始终跟随玩家播放。
- 氛围音效会在特定条件下播放，条件计算方法参见环境音效 § 氛围算法。氛围音效的声音音量会线性衰减。

数据类型较复杂（见下），默认为空对象，仅接受
```

```

修饰符。不可插值，获取位置为摄像机的位置。

- [图:NBT复合标签/JSON对象] - [图:字符串][图:NBT复合标签/JSON对象]loop：控制循环音效。 - - 声音事件，见Template:Nbt inherit/sound event/source - [图:NBT复合标签/JSON对象]mood：控制氛围音效。 - [图:字符串][图:NBT复合标签/JSON对象]*sound：氛围音效使用的声音事件。 - - 声音事件，见Template:Nbt inherit/sound event/source - [图:整型]*tick_delay：两次播放间的最小延迟。 - [图:整型]*block_search_extent：决定了氛围音效播放位置的正方体范围的大小。此正方体范围以玩家为中心，棱长为此值的2倍。 - [图:双精度浮点数]*offset：值越大，声源距离玩家越远。 - [图:NBT列表/JSON数组]*additions：控制附加音效。 - [图:NBT复合标签/JSON对象] - [图:字符串][图:NBT复合标签/JSON对象]*sound：附加音效使用的声音事件。 - - 声音事件，见Template:Nbt inherit/sound event/source - [图:双精度浮点数]*tick_chance：每一游戏刻中开始播放的概率。高于1的值相当于1，低于0的值相当于0。

# 环境属性修饰符

环境属性修饰符（Environment Attribute Modifiers）是游戏进行修饰操作的方法。游戏在进行环境属性之间的计算时，会使用到3个参数：

- 输入值：此上下文将被修改的值。
- 参数值：修饰符进行修饰时的附加参数。
- 修饰符类型

不同的场合会使用不同的修饰符格式，但都具有这三个参数，其中输入值由游戏自动获取，参数值必须手动提供，修饰符类型可选。

为便于展示，下文使用环境属性映射的格式展示修饰符。

## 覆写修饰符

“覆写（override）”即直接使用一个新的值覆盖相应的环境属性值。

当直接设置一个环境属性ID到其对应值的映射时，将隐式使用
```
override
```

修饰符：

- [图:任意类型]<环境属性ID>：要设置的环境属性值。需要与相应环境属性的数据类型对应。

或者也可以显式定义
```
override
```

修饰符：

- [图:NBT复合标签/JSON对象]<环境属性ID> - [图:字符串]modifier： ``` override ``` - [图:任意类型]argument：要设置的环境属性值。需要与相应环境属性的数据类型对应。

能够使用以下通用修饰符的环境属性都可以使用覆写修饰符来直接设值。

## 布尔修饰符

此类修饰符用于修饰布尔值。

- [图:NBT复合标签/JSON对象]<环境属性ID> - [图:字符串]*modifier：要应用的布尔修饰符。 - [图:布尔型]*argument：提供的布尔值，用于修饰符计算。

可用修饰符如下：

- ``` and ``` ：与操作，仅当输入值与参数值均为 ``` true ``` 时为 ``` true ``` 。
- ``` nand ``` ：与非操作，仅当输入值与参数值均为 ``` true ``` 时为 ``` false ``` 。
- ``` or ``` ：或操作，仅当输入值与参数值均为 ``` false ``` 时为 ``` false ``` 。
- ``` nor ``` ：或非操作，仅当输入值与参数值均为 ``` false ``` 时为 ``` true ``` 。
- ``` xor ``` ：异或操作，仅当输入值与参数值不同时为 ``` true ``` 。
- ``` xnor ``` ：同或操作，仅当输入值与参数值相同时为 ``` true ``` 。

## 浮点修饰符

此类修饰符用于修饰浮点数。

- ``` add ``` ：将输入值与参数值作和。

- ``` multiply ``` ：将输入值与参数值作积。

## 颜色修饰符

此类修饰符用于修饰颜色。不论是哪种修饰符，每个通道的计算结果都会钳制在
```
[0, 255]
```

之间。

颜色修饰符分为两类：RGB颜色修饰符和ARGB颜色修饰符，分别修饰RGB颜色和ARGB颜色。

- [图:NBT复合标签/JSON对象]<环境属性ID> - [图:字符串]*modifier：要应用的颜色修饰符。 - - 如果颜色修饰符是 ``` alpha_blend ``` ，附加参数如下： - [图:字符串][图:整型][图:NBT列表/JSON数组]*argument：提供的ARGB颜色，用于修饰符计算。 - - ARGB颜色，见Template:Nbt inherit/string argb color/source - - 如果颜色修饰符是 ``` blend_to_gray ``` ，附加参数如下： - [图:NBT复合标签/JSON对象]*argument：提供的ARGB颜色，用于修饰符计算。 - [图:单精度浮点数]*brightness：（0≤值≤1）应用到灰度值的倍率。 - [图:单精度浮点数]*factor：（0≤值≤1）计算使用的因子。 - - 对于其他颜色修饰符，附加参数如下： - - 如果是RGB颜色修饰符，则必须使用RGB颜色： - [图:字符串][图:整型][图:NBT列表/JSON数组]*argument：提供的颜色，用于修饰符计算。 - - RGB颜色，见Template:Nbt inherit/string rgb color/source - - 如果是ARGB颜色修饰符，则可以使用RGB颜色和ARGB颜色： - [图:字符串][图:整型][图:NBT列表/JSON数组]*argument：提供的颜色，用于修饰符计算。如果提供RGB颜色，则不允许字符串格式，游戏会将其A通道视为255。 - - RGB颜色，见Template:Nbt inherit/rgb color/source - - ARGB颜色，见Template:Nbt inherit/string argb color/source

可用修饰符如下：

- ``` add ``` ：将输入值与参数值作和。每个通道单独计算。
- ``` subtract ``` ：将输入值与参数值作差。即输入值减去参数值，每个通道单独计算。
- ``` multiply ``` ：将输入值与参数值作积。每个通道单独计算。
- ``` alpha_blend ``` ：对颜色进行alpha混合。对于输入值的通道K而言的计算结果为 ``` K * (1 + A/255) ``` ，R、G、B、A四个通道均进行计算。 - A通道为1时，实质上就是使用参数值进行覆盖操作。
- ``` blend_to_gray ``` ：对输入值进行灰度处理，计算的亮度和因子由参数提供。 - 先计算灰度 ``` gray ``` ： ``` brightness * (0.3 * R + 0.59 * G + 0.11 * B) ``` ，其中RGB为输入值的通道值。 - 再计算输出值的对应通道： ``` lerp(factor, < 输入颜色对应通道 >, gray) ``` ，即输入颜色的对应通道与灰度区间上以因子作为采样点经线性插值得到的值。

# 其他用法

战利品表谓词
```
environment_attribute_check
```

可以判断服务端的某个环境属性是否为精确值。

数值提供器
```
environment_attribute
```

可以获取数值类型（浮点数和天体角度，不包括颜色）的服务端的环境属性的值，以供给战利品表系统和村民交易系统相关的计算。

注：在这些场景中，游戏只会获取服务端的环境属性，且获取的位置始终为战利品上下文参数
```
origin
```

提供的位置。
