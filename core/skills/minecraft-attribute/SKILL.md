本条目介绍的是生物的属性。关于命令，请见“命令/attribute”；关于世界系统中的属性，请见“环境属性”。

属性（Attributes）是生物的增益/减益特性系统。属性也存在修饰符（Modifiers）和增益（Buffs），用于调整属性的强度。

# 属性

每个独立的属性都控制着生物的一些能力，例如攻击伤害和速度等。所有的属性值都是双精度浮点数/单精度浮点数。

在Java版中，属性有以下基本属性：

- 值域是属性的计算值不能逾越的范围，计算值在值域外时会被钳制至值域的最小值或最大值。
- 类型表示属性效果的好坏，影响其修饰符在提示框中的颜色： - 增加正面属性值的修饰符为蓝色，减少正面属性值的修饰符为红色。 - 增加负面属性值的修饰符为红色，减少负面属性值的修饰符为蓝色。 - 中性属性值的修饰符为灰色。
- 属性有其适用的生物，在非适用的生物上不存在。
- 属性的默认值是每一个属性实例的基值的默认值。

每一个生物上的每一个属性有以下数据：

- 基值（Base）是该属性对于该生物，被应用修饰符前的值。
- 修饰符（Modifiers）用于修饰属性，改变其计算值。

生物的属性最终以计算值生效。

在基岩版中，属性有以下基本属性：

- 重定义模式是属性在通过组件组重新定义时如何更新自己的当前值。 - 保持当前值意味着重新定义时，当前值不会随着默认值被修改而改变。当前值恰好等于当前最大值、当前值比新定义的默认最小值还小、确实存在属性修饰符并导致计算值与默认值不同时除外，此时当前值分别会被设置为新的默认值、设置为新的默认最小值和设置为计算值。 - 更新至新的默认值意味着重新定义时，当前值会被直接更新为新的默认值。确实存在属性修饰符并且计算值与默认值相同时除外，此时当前值会保留旧的值不变。
- 是否同步表示属性是否会随着网络从服务器同步到客户端。
- 属性有其适用的生物，默认在非适用的生物上不存在。但是通过附加包，可以使任何游戏内存在的属性类型在任何生物上存在。

每一个生物上的每一个属性有以下数据：

- 默认最小值、默认最大值和默认值是该属性对于该生物，被应用修饰符前的值，这里的第三个值也可以称作基值（Base）。
- 当前最小值、当前最大值和当前值是该属性对于该生物，被应用修饰符和增益之后的值。在应用修饰符和增益期间，运算数取0、1、2分别代表修改最小值、最大值和当前值，该数字会在持久化时存储在修饰符和增益对应的NBT标签中。
- 修饰符（Modifiers）用于修饰属性，计算得到当前最小值、当前最大值和一个计算值，其中计算值会根据重定义模式来确定是否会被前二者钳制后应用至当前值。
- 增益（Buffs）用于临时对一个属性的三种当前类型的值直接进行修改。 - 瞬时增益在添加到属性上时便瞬时生效，然后结束其生命周期。 - 临时增益在添加到属性上后每游戏刻检查生效，并在既定的生命周期结束后从属性上移除。

生物的属性最终以当前值生效。

# 修饰符

修饰符会修饰一个属性的基值/三种默认类型的值，并以此更新三种当前类型的值。

在Java版中，和属性一样，修饰符也具有命名空间ID（
```
id
```

）。修饰符的ID或名称与它的具体效果无关，而由它的作用属性类型（
```
type
```

）、运算模式（
```
operation
```

）和修饰值（
```
amount
```

）决定。在基岩版中，修饰符具有一个UUID、一个名称、一个运算模式和一个运算数四种基本属性，以及一个修饰值。

任意修饰值的极限即为双精度浮点数/单精度浮点数的极限。但无论总修饰值为多少，修饰后的计算值仍会被钳制于该属性的值域间。

## 来源

除命令外，生物会受物品（包括其上的魔咒）、状态效果、所处位置和实体数据的影响添加或移除属性修饰符。

属性修饰符的来源为物品时，此物品必须置于指定生物槽位中。如果物品有耐久度，则剩余耐久度为0时，修饰符也不会生效。

如果两个修饰符具有相同的ID/四种基本属性完全相同且作用于同一个属性，那么后加入的修饰符会替代先加入的修饰符生效/失效，而不会将它们相叠加。

## 持久化

不是所有修饰符都会持久地保留在生物的数据中。在Java版中，可持久化的修饰符可以通过
```
/
data
```

等命令获取，而不可持久化的修饰符无法通过
```
/
attribute
```

之外的命令获取。无论修饰符是否能持久化，其对属性计算值的影响无差异。生物在持久化保存到文件时不会带有这些不可持久化的修饰符数据，即不可持久化的修饰符只存在于内存中。

所有魔咒属性效果修饰符、物品修饰符都属于不可持久化的修饰符，而所有状态效果修饰符都是可持久化的修饰符。

## 行为

在使用某项属性时，系统会使用这项属性的基值/三种默认值与所有对此属性生效的修饰符进行计算，得出最终的当前最小值、最终的当前最大值和当前值的计算值，并根据重定义模式决定是否将计算值赋给当前值。

在Java版中，一般情况下，提示框会显示物品能赋予的修饰符。

- 这些修饰符包括： - 物品堆叠组件 ``` attribute_modifiers ``` 中指定ID的修饰符 - 魔咒属性效果中的修饰符 - 状态效果生效时赋予的修饰符
- 修饰值在提示框中保留2位小数。
- 如果修饰符的值为0，提示框中不会显示修饰值。
- 如果 ``` attribute_modifiers ``` 组件中的修饰符ID为 ``` base_attack_damage ``` 或 ``` base_attack_speed ``` ，此修饰符会无视其类型和零值对显示的影响，在提示框中显示为深绿色。相较非基础修饰符，这些修饰符向右偏移一个空白，同时不显示“+”号（负号会正常显示）。 - ``` base_attack_damage ``` 修饰符在提示框的显示值为此物品修饰值与 ``` attack_damage ``` 属性基值的和。 - ``` base_attack_speed ``` 修饰符在提示框的显示值为此物品修饰值与 ``` attack_speed ``` 属性基值的和。
- 被解析为 ``` Infinity ``` 或 ``` -Infinity ``` 的修饰值在提示框中分别显示为“∞”或“-∞”。

## 运算模式

属性修饰符的运算模式（Operation）决定了它修改基值/三种类型的值的方式。游戏按照固定顺序同时分别对三种类型的值执行以下三种操作：

增量操作（add_value，Op0）
属性基值/某一种类型的默认值加上指定增量值。
设该操作运算后的值为Result0，则Result0=base+∑Op0i，其中base代表被该操作修饰前的属性基值，Op0i代表第i个参与运算的Op0修饰符的值。
例：给定增量操作
```
{amount:2,operation:'add_value'}
```

和
```
{amount:4,operation:'add_value'}
```

，它们一同修饰基值为3的某个属性，则修饰过程为
```
3+(
2
+
4
)=9
```

。
倍率操作（add_multiplied_base，Op1）
对增量操作完成后的值进行加倍。
设该操作运算后的值为Result1，则Result1=Result0×(1+∑Op1i)，其中Op1i代表第i个参与运算的Op1修饰符的值。
例：在上一例的基础上又给定倍率操作
```
{amount:3,operation:'add_multiplied_base'}
```

和
```
{amount:6,operation:'add_multiplied_base'}
```

，则修饰过程为
```
9×(1+
3
+
6
)=90
```

。
最终倍乘操作（add_multiplied_total，Op2）
对倍率操作完成后的值进行连续加倍。
设该操作运算后的值为Result2，则Result2=Result1×∏(1+Op2i)，其中Op2i代表第i个参与运算的Op2修饰符的值。
例：在上一例的基础上又给定最终倍乘操作
```
{amount:2,operation:'add_multiplied_total'}
```

和
```
{amount:4,operation:'add_multiplied_total'}
```

，则修饰过程为
```
90×(1+
2
)×(1+
4
)=1350
```

。
总公式：(base+∑Op0i)×(1+∑Op1j)×∏(1+Op2k)，其中base代表属性基值，Op0i,Op1j,Op2k分别代表参与运算的第i个Op0修饰符的值、第j个参与运算的Op1修饰符的值、第k个参与运算的Op2修饰符的值。

在基岩版中，对于当前值的计算值，还会检测重定义模式，并且依据不同的重定义模式决定保留旧的当前值还是使用新的计算值作为当前值。在此之后，最终还会当前的当前值对进行清洗操作：

清洗操作（cap，Op3）
对计算值设置封顶并进行钳制。
设该操作运算后的值为Result3，则Result3=clamp(Result2current,Result2currentMin,min⁡(Result2currentMax,Op3i))，其中Op3i代表第i个参与运算的Op3修饰符的值。

# 增益

本段落所述内容仅适用于基岩版。
增益分为瞬时增益（Instantaneous Buff）和临时增益（Temporal Buff），用于增加或减少三种当前类型的值。增益具有一个ID（可能会由一个名称使用FNV-1a哈希算法生成，也可能直接赋予）、一个类型和一个运算数三种基本属性，以及一个增益值。临时增益还额外有持续时间基本属性，以及一个当前的生命周期计时器。虽然增益理论上可以施加在任意运算数上，但游戏内目前只有施加在当前值上的情况的使用情景。一些增益还会带有一个伤害来源的基本属性，这包含来源的实体和一个伤害类型。

## 持久化

无论如何，瞬时增益都不可持久化。而对于临时增益，只有一部分可持久化。无论一个临时增益是否能持久化，其对属性增益值的影响无差异。生物在持久化保存到文件时不会带有这些不可持久化的增益数据，即不可持久化的增益只存在于内存中。

## 类型

每种类型具有一个整数作为ID，用于在持久化时存储在对应的NBT标签中。

## 行为

值的增益通过加法的方式作用，但允许加一个负值以实现减法的效果，例如对于
```
minecraft:health
```

属性，正值和负值分别代表治疗和伤害。增益可能不会成功生效，也有可能不以默认方式生效，例如
```
minecraft:damage_sensor
```

组件可能会阻挡添加到
```
minecraft:health
```

属性上的增益，
```
minecraft:absorption
```

属性可能会“转移”添加到
```
minecraft:health
```

属性上的增益到自身，手持不死图腾可能会直接使该增益的效果变为“将当前值设置为
```
1.0
```

”等等。

# 应用

 参见：命令/attribute和数据组件 § attribute_modifiers 
当属性修饰符应用到一个物品或生物时，它可以将拥有者的某项属性进行修正。

## Java版

下面的命令会给予命令执行者一个属性修饰符，以使其变大：

```
/
attribute
 @s minecraft:scale modifier add scale_bonus 0.25 add_value
```

下面的命令将给予命令执行者一把在主手中增加20（[图:♥] × 10）点额外伤害的钻石剑：

```
/
give
 @s diamond_sword[attribute_modifiers=[{type:"attack_damage", id:"minecraft:base_attack_damage", slot:"mainhand", amount:20, operation:"add_value"}]]
```

下面的命令将召唤一个僵尸，当玩家接近它100格时就会被它发现，而不是通常的35格：

```
/
summon
 zombie ~ ~ ~ {attributes:[{id:"follow_range",base:100.0d}]}
```
