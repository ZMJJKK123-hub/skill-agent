本条目介绍的是用于游戏存储方块结构的存储格式。关于相似的用于社区程序的格式，请见“Schematic文件格式”。

 关于基岩版中由结构方块保存的类似文件，请见“基岩版结构文件”。

本条目所述内容仅适用于Java版。
结构存储文件，又称结构模板（Structure Template），是游戏存储方块结构的一种文件。它既作为游戏的基础数据，控制世界生成；也可以由玩家指定创建，保存在存档中。

# 存储格式

在游戏本体client.jar内，结构存储文件全部位于
```
/data/minecraft/structure
```

目录下。每个存档中，由玩家导出的结构存储文件位于
```
<
存档根目录
>/generated/<
命名空间
>/structure/<
名称
>.nbt
```

。在数据包中，结构存储文件位于
```
data/<
命名空间
>/structure
```

目录下。

当游戏引用结构模板时，会优先使用存档根目录下的结构模板，若无则使用数据包内的结构模板，否则使用游戏本体内置的结构模板。

结构存储文件使用GZip压缩的NBT文件格式保存，其内部有下列NBT结构：

- [图:NBT复合标签/JSON对象] 根标签 - [图:整型]*DataVersion：保存此结构存储文件的游戏的数据版本。如果此项不存在则游戏认为此项是500（Java版1.9.4之后，Java版1.10快照之前）。 - [图:NBT列表/JSON数组]* *blocks：方块结构内具有的方块。 - [图:NBT复合标签/JSON对象]：一个方块结构内的方块。 - [图:NBT列表/JSON数组]* *pos：方块相对于原点（方块结构范围的最小点）的坐标。内部有3个元素。 - [图:整型]：方块的X坐标。 - [图:整型]：方块的Y坐标。 - [图:整型]：方块的Z坐标。 - [图:NBT复合标签/JSON对象]nbt：与此方块相关的方块实体的数据。 - 见方块实体数据格式。不包含[图:整型]x、[图:整型]y、[图:整型]z。 - [图:整型]* *state：映射到调色板内的下标。游戏将根据调色板内指定下标的数据获取此处要放置的方块状态。 - [图:NBT列表/JSON数组]* *entities：方块结构内包含的实体的信息。 - [图:NBT复合标签/JSON对象]：一个实体的信息。游戏在放置实体时将以结构生成的方式放置此实体。 - [图:NBT列表/JSON数组]* *blockPos：实体相对于原点（方块结构范围的最小点）的方块坐标。此项用于检测实体是否在方块结构范围内，如果不在则不能放置。内部有3个元素。 - [图:整型]：方块坐标的X分量。 - [图:整型]：方块坐标的Y分量。 - [图:整型]：方块坐标的Z分量。 - [图:NBT列表/JSON数组]* *pos：实体相对于原点（方块结构范围的最小点）的坐标。内部有3个元素。 - [图:双精度浮点数]：实体的X坐标。 - [图:双精度浮点数]：实体的Y坐标。 - [图:双精度浮点数]：实体的Z坐标。 - [图:NBT复合标签/JSON对象]* *nbt：实体的数据。 - 见实体数据格式。其中[图:整型数组]UUID会被忽略，[图:NBT列表/JSON数组]Pos会被覆写，[图:NBT列表/JSON数组]Passengers无效。 - [图:NBT列表/JSON数组]palette：（与[图:NBT列表/JSON数组]palettes中必须存在一个）方块调色板，即定义数字与方块状态的映射，以降低文件体积。 - [图:字符串][图:NBT复合标签/JSON对象]：该下标在调色板中对应的方块状态。 - - 方块状态，见Template:Nbt inherit/block state/source - [图:NBT列表/JSON数组]palettes：（与[图:NBT列表/JSON数组]palette中必须存在一个）方块调色板集合，游戏在放置方块结构时随机挑选其中一种调色板进行放置。此项与[图:NBT列表/JSON数组]palette互斥，且此项加载更加优先。 - [图:NBT列表/JSON数组]：一个方块调色板。 - [图:字符串][图:NBT复合标签/JSON对象]：该下标在调色板中对应的方块状态。 - - 方块状态，见Template:Nbt inherit/block state/source - [图:NBT列表/JSON数组]* *size：方块结构的大小。内部有3个元素。 - [图:整型]：方块结构在X轴上的长度。 - [图:整型]：方块结构在Y轴上的高度。 - [图:整型]：方块结构在Z轴上的长度。

# SNBT格式

结构模板具有独特的SNBT格式，使用SNBT文件格式保存。

SNBT格式的结构模板目前可以由数据生成器转换NBT格式的结构模板得到。游戏在执行NBT与SNBT的转换时，会对结构模板进行额外处理，与方块集合相关的标签不完全符合NBT与SNBT的转换规则。而[图:整型]DataVersion、[图:NBT列表/JSON数组]entities和[图:NBT列表/JSON数组]size会正常转换，以下不再写出。

SNBT格式的结构模板没有任何用处。虽然游戏内存在SNBT格式的结构模板的导出方法，但是全被禁用。

- [图:NBT复合标签/JSON对象] 根标签 - [图:NBT列表/JSON数组]* *data：方块结构内具有的方块。 - [图:NBT复合标签/JSON对象]：一个方块结构内的方块。 - [图:NBT列表/JSON数组]* *pos：方块相对于原点（方块结构范围的最小点）的坐标。内部有3个元素。 - [图:整型]：方块的X坐标。 - [图:整型]：方块的Y坐标。 - [图:整型]：方块的Z坐标。 - [图:字符串]* *state：此方块的详细数据，格式遵守 ``` < 方块ID >{< 方块属性 >:< 值 >, ...} ``` 。 - [图:NBT复合标签/JSON对象]nbt：与此方块相关的方块实体的数据。 - 见方块实体数据格式。不包含[图:整型]x、[图:整型]y、[图:整型]z。 - [图:NBT列表/JSON数组]palette：方块调色板。 - [图:字符串]：调色板中的一个方块，格式遵守 ``` < 方块ID >{< 方块属性 >:< 值 >, ...} ``` 。 - [图:NBT列表/JSON数组]palettes：方块调色板集合。 - [图:NBT复合标签/JSON对象]：一个方块调色板。 - [图:字符串]* *<方块ID>{<方块属性>:<值>, ...}：上述[图:NBT列表/JSON数组]data中的方块在此调色板下实际使用的方块，此标签内容的格式与标签名相同。

# 存储行为

结构存储文件可以使用结构方块和测试实例方块进行保存和加载。

在游戏内，部分结构使用结构存储文件生成一块块结构片段。这些结构存储文件中包含了用于标记的结构方块和拼图方块，游戏在放置这些方块结构时会进行后期处理以替换掉这些方块。部分结构也需要阻止方块被即将要放置的方块替换，即阻止方块的放置以保留原有的方块。

- 雪屋、下界化石、海底废墟、废弃传送门和沉船使用结构存储文件时会对结构存储文件的内容进行部分修改，包括调整位置和修改方块等。
- 末地城、雪屋、海底废墟、沉船、林地府邸会对方块结构内模式是数据模式的结构方块进行后处理，按照数据[图:字符串]metadata的值进行判断： - 末地城结构片段处理下列值： - ``` Chest< 任意字符串 > ``` - 设置此位置下方的箱子的战利品表为 ``` chests/end_city_treasure ``` 。 - ``` Elytra< 任意字符串 > ``` - 将此位置替换为带有鞘翅的物品展示框。 - ``` Sentry< 任意字符串 > ``` - 将此位置替换为一只潜影贝。 - 雪屋结构片段处理下列值： - ``` chest ``` - 设置此位置下方的箱子的战利品表为 ``` chests/igloo_chest ``` 。 - 海底废墟结构片段处理下列值： - ``` chest ``` - 将此位置替换为含水的箱子，且战利品表为 ``` chests/underwater_ruin_big ``` （大型海底废墟）或 ``` chests/underwater_ruin_small ``` （小型海底废墟）。 - ``` drowned ``` - 将此位置替换为一只溺尸。如果成功生成，检查此处是否高于海平面，如果高于则此处替换为空气，否则替换为水。 - 沉船结构片段处理下列值： - ``` map_chest ``` - 设置此位置下方的箱子的战利品表为 ``` chests/shipwreck_map ``` 。 - ``` supply_chest ``` - 设置此位置下方的箱子的战利品表为 ``` chests/shipwreck_supply ``` 。 - ``` treasure_chest ``` - 设置此位置下方的箱子的战利品表为 ``` chests/shipwreck_treasure ``` 。 - 林地府邸结构片段处理下列值： - ``` Chest< 任意字符串 > ``` - 将此位置替换为箱子，面朝北方，战利品表为 ``` chests/woodland_mansion ``` 。 - ``` ChestEast ``` - 将此位置替换为箱子，在面朝东方的基础上，被结构片段再次旋转获得最终朝向，战利品表为 ``` chests/woodland_mansion ``` 。 - ``` ChestNorth ``` - 将此位置替换为箱子，在面朝北方的基础上，被结构片段再次旋转获得最终朝向，战利品表为 ``` chests/woodland_mansion ``` 。 - ``` ChestSouth ``` - 将此位置替换为箱子，在面朝南方的基础上，被结构片段再次旋转获得最终朝向，战利品表为 ``` chests/woodland_mansion ``` 。 - ``` ChestWest ``` - 将此位置替换为箱子，在面朝西方的基础上，被结构片段再次旋转获得最终朝向，战利品表为 ``` chests/woodland_mansion ``` 。 - ``` Group of Allays ``` - 将此位置替换为1-3只悦灵。 - ``` Mage ``` - 将此位置替换为一只唤魔者。 - ``` Warrior ``` - 将此位置替换为一只卫道士。
- 对于末地城、雪屋、下界化石、海底废墟、废弃传送门、沉船和林地府邸，方块结构内的拼图方块会被替换为对应的[图:字符串]final_state。
- 所有使用结构存储文件的结构均阻止结构方块被放置。
- 使用 ``` legacy_single_pool_element ``` 的结构模板阻止空气被放置。
- 使用 ``` single_pool_element ``` 或 ``` legacy_single_pool_element ``` 的结构模板会展开放置拼图方块内的拼图结构。
- 使用处理器列表[图:字符串][图:NBT复合标签/JSON对象][图:NBT列表/JSON数组]processors可以后处理结构模板内的方块。
