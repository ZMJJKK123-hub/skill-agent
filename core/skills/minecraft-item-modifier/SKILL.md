本条目所述内容仅适用于Java版。

物品修饰器（Item modifier），也作战利品修饰器（Loot modifiers）、战利品表函数（Loot functions）、物品函数（Item functions），是数据包中的技术性JSON文件，存储在数据包的
```
data/<命名空间>/item_modifier
```

目录下。物品修饰器可在战利品表中为物品添加战利品表物品函数。命令
```
/
item
```

可调用数据包中有效的物品修饰器以修改物品。

# 定义

物品修饰器本质上是战利品表物品函数（Loot item function）。基本上所有战利品表物品函数都是条件性函数（Loot item conditional function）——可包含若干战利品表物品条件。

在数据包中，物品修饰器可用于对物品施加单个或多个修改操作。这些操作均使用JSON格式来定义，故每个物品修饰器文件均是一个JSON文件。原版游戏内不存在默认的物品修饰器，只能通过添加额外的数据包来创建。

物品修饰器可以通过
```

```
/

## 通过战利品表

战利品表文件也使用物品修饰器。很多时候，调用战利品表文件同时也伴随着一个物品修饰器的调用。这个被调用的物品修饰器可能并非以一个单独的文件存在，而是直接定义在战利品表的JSON片段中。当然，你也可以使用“reference”物品修饰器来引用一个物品修饰器文件——有时候，相比于直接在战利品表中定义，这样会更加灵活和方便。

# 数据格式

## 基本格式

- [图:NBT复合标签/JSON对象][图:NBT列表/JSON数组] 物品修饰器的根元素，可以是一个单独的物品修饰器[图:NBT复合标签/JSON对象]对象或者是包含多个物品修饰器[图:NBT复合标签/JSON对象]对象的[图:NBT列表/JSON数组]数组。 - [图:NBT列表/JSON数组]conditions：一个战利品表谓词列表。当其中的条件全部通过时才会应用本函数。 - [图:NBT复合标签/JSON对象]：一个战利品表谓词。关于此标签的结构，参见战利品表谓词页面。 - [图:字符串]function：物品修饰器的类型，为一个命名空间ID。可用的类型将在下方列出。 - 物品修饰器属性。每种类型的物品修饰器都有自己独特的属性，参见下文。

## 物品修饰器类型

以下列出所有的物品修饰器类型及其相应属性。每种类型的修饰器名称即为[图:字符串]function的一个可能取值。

下列物品修饰器中，在原有物品堆叠基础上增加物品数量的，如果原有物品堆叠的物品数量为负数，其会被重置到0后再增加数量。应用完所有修饰器后，如物品堆叠的物品数量小于等于0，该堆叠将被设置为空。

### apply_bonus

根据指定魔咒的等级，增加物品数量。

- - [图:字符串]enchantment：用来进行魔咒等级计算的魔咒ID。 - [图:字符串]formula：计算公式。可选值为 ``` uniform_bonus_count ``` （均匀分布随机数）、 ``` ore_drops ``` （矿物掉落随机算法）和 ``` binomial_with_bonus_count ``` （二项分布随机数）。 - [图:NBT复合标签/JSON对象]parameters：计算所需的参数。 - - 如果[图:字符串]formula是 ``` uniform_bonus_count ``` ，则返回均匀分布的随机整数，值域为[c,c+bl]，其中l是魔咒等级，c是原物品数量： - [图:整型]bonusMultiplier：均匀分布中的乘数，即公式中的b。 - - 如果[图:字符串]formula是 ``` ore_drops ``` ，则为矿物掉落算法。如果魔咒等级l为0，则返回原物品数量c；如果魔咒等级l大于0，则最终物品数量可以根据魔咒等级翻倍，最高可以为原数量的l+1倍。 - - 如果[图:字符串]formula是 ``` binomial_with_bonus_count ``` ，则计算二项分布随机数。物品最终的数量为原数量与这个二项分布随机数的和。 - [图:整型]extra：额外计算的次数。二项分布计算的n为魔咒等级与额外计算次数之和。 - [图:单精度浮点数]probability：二项分布中的概率p。

### copy_components

从[图:字符串]*source指定的数据源中获取数据组件并复制到物品中。

- - [图:NBT列表/JSON数组]exclude：选择排除指定的数据组件。 - [图:字符串]：数据组件的命名空间ID。 - [图:NBT列表/JSON数组]include：选择复制指定的数据组件。如果此项不存在则复制除[图:NBT列表/JSON数组]exclude指定的数据组件外的所有数据组件。 - [图:字符串]：数据组件的命名空间ID。 - [图:字符串]*source：数据源类型。可以为 ``` block_entity ``` （方块实体）、 ``` this ``` （执行战利品生成的实体）、 ``` attacker ``` （杀死本实体的实体）、 ``` attacking_player ``` （杀死本实体的玩家）、 ``` direct_attacker ``` （进行直接击杀本实体的实体）、 ``` tool ``` （参与交互的物品）、 ``` target_entity ``` （交互行为中的目标实体）和 ``` interacting_entity ``` （交互行为的执行实体）。

### copy_custom_data

复制NBT到
```
custom_data
```

物品堆叠组件中。

- - [图:NBT列表/JSON数组]ops：一系列复制操作。 - [图:NBT复合标签/JSON对象]：一个具体的复制操作。 - [图:字符串]op：操作类型。可以为 ``` replace ``` （以[图:字符串]source所选标签替换[图:字符串]target所选标签）、 ``` append ``` （将[图:字符串]source所选标签复制到[图:字符串]target所选的[图:NBT列表/JSON数组]列表标签的末尾）或 ``` merge ``` （复制[图:字符串]source所选标签，然后合并到[图:字符串]target所选的[图:NBT复合标签/JSON对象]复合标签中）。 - [图:字符串]source：一个NBT路径，表示被复制的标签（1个或多个）。路径的首个节点代表源NBT数据根标签下的一个子节点。 - [图:字符串]target：一个NBT路径，表示要复制到的标签（1个或多个）。路径的首个节点代表目标物品的 ``` custom_data ``` 物品堆叠组件下的一个子标签。例如，若 ``` target ``` 的值设为 ``` example_tag ``` ，则将会选中物品的 ``` components.'minecraft:custom_data'.example_tag ``` 标签。 - [图:字符串][图:NBT复合标签/JSON对象]source：指定NBT的复制源。复制源可以为实体、方块实体，或命令存储。若为字符串，则会指定一个实体或方块实体，值与下方[图:字符串]target相同。 - [图:字符串]type：复制源的类型。可以为 ``` context ``` （实体或方块实体）或 ``` storage ``` （命令存储）。 - - 若[图:字符串]type为 ``` context ``` ，还需附加标签： - [图:字符串]target：指定作为复制源的实体或方块实体。可以为 ``` block_entity ``` （物品对应方块的方块实体）、 ``` this ``` （执行战利品生成的实体）、 ``` attacker ``` （杀死本实体的实体）、 ``` attacking_player ``` （杀死本实体的玩家）、 ``` direct_attacker ``` （进行直接击杀本实体的实体）、 ``` target_entity ``` （交互行为中的目标实体）和 ``` interacting_entity ``` （交互行为的执行实体） - - 若[图:字符串]type为 ``` storage ``` ，还需附加标签： - [图:字符串]source：（命名空间ID）表示一个作为复制源的命令存储。

将实体、附魔台和旗帜的自定义名称设置到物品的

- - [图:字符串]source：指定名称的来源实体或方块实体。可以为 ``` this ``` （执行战利品生成的实体）、 ``` attacker ``` （伤害本实体的实体）、 ``` last_damage_player ``` （伤害本实体的玩家）、 ``` block_entity ``` （物品对应方块的方块实体）、 ``` direct_attacker ``` （进行直接击杀本实体的实体）、 ``` target_entity ``` （交互行为中的目标实体）和 ``` interacting_entity ``` （交互行为的执行实体）。

### enchanted_count_increase

决定了指定魔咒对该物品数量的影响。物品数量首先会加上
```
round(<
count
>*<
魔咒等级
>)
```

，其中
```
round(<
数
>)
```

表示四舍五入；如[图:整型]limit不为0，则还会限制上一步得到的物品数量为不超过该值。

- - [图:整型][图:NBT复合标签/JSON对象]count：每等级魔咒使得物品需要增加的数量。 - - 数值提供器，见战利品表/数值提供器 - [图:字符串]enchantment：提供魔咒等级的魔咒命名空间ID。 - [图:整型]limit：物品的最大数量，超过此数量会被强制限制在此数量。如果设置为0，则无限制。

### enchant_randomly

为物品附上一个随机的魔咒。魔咒的等级也是随机的。

- - [图:布尔型]only_compatible：（可选，默认为 ``` true ``` ）指定是否只添加能附在此物品上的魔咒，书没有此限制。 - [图:字符串][图:NBT列表/JSON数组]options：（可选，默认为所有魔咒）能够附上的魔咒。可以为一个魔咒的命名空间ID或一个魔咒标签，也可以为命名空间ID组成的数组。为物品添加魔咒时会随机选取一个魔咒。 - [图:字符串]：一项魔咒的命名空间ID。 - [图:布尔型]include_additional_cost_component：（默认为 ``` false ``` ）是否根据魔咒等级增加村民收购物品数量，需要战利品上下文参数 ``` additional_cost_component_allowed ``` 才可生效，详见村民交易定义格式。

### enchant_with_levels

- - [图:整型][图:NBT复合标签/JSON对象]levels：指定附魔等级。 - - 数值提供器，见战利品表/数值提供器 - [图:字符串][图:NBT列表/JSON数组]options：（可选，默认为所有魔咒）能够附上的魔咒。可以为一个魔咒的命名空间ID或一个魔咒标签，也可以为命名空间ID组成的数组。为物品添加魔咒时会随机选取一个魔咒。 - [图:字符串]：一项魔咒的命名空间ID。 - [图:布尔型]include_additional_cost_component：（默认为 ``` false ``` ）是否根据附魔等级增加村民收购物品数量，需要战利品上下文参数 ``` additional_cost_component_allowed ``` 才可生效，详见村民交易定义格式。

### exploration_map

将普通的地图物品变为一个指引到某个结构的探险家地图。如果物品不是地图，则不做任何处理。
为探险家地图物品添加结构定位信息。如果物品堆叠为空或未找到结构，则不做任何处理。

- - [图:字符串]decoration：结构在地图中显示的地图图标ID，游戏会同步根据图标修改地图的着色。如果不存在则默认为 ``` mansion ``` （林地府邸的地图图标）。 - [图:字符串]destination：结构标签命名空间ID，包含要指向的结构，不带 ``` # ``` 前缀。如果不存在则默认为 ``` on_treasure_maps ``` （仅包含埋藏的宝藏）。 - [图:整型]search_radius：（默认为50）搜寻的区块半径，使用切比雪夫距离。 - [图:布尔型]skip_existing_chunks：（默认为 ``` true ``` ）是否不在已经生成过的区块搜寻。 - [图:字节型]zoom：（默认为2）地图缩放等级。

### explosion_decay

如果物品是因为方块被爆炸破坏而产生，执行该函数的每个物品有1/爆炸半径的概率消失，堆叠的物品会被分为多个单独的物品计算；否则此物品修饰器不做任何处理。

### discard

将物品堆叠替换为空堆叠。

### fill_player_head

将玩家的头设置为指定玩家的头。如果物品不是玩家的头则不做任何处理。

- - [图:字符串]entity：用于设置该玩家头颅的玩家。可以为 ``` this ``` （执行战利品生成的实体）、 ``` attacker ``` （杀死本实体的实体）、 ``` attacking_player ``` （杀死本实体的玩家）、 ``` direct_attacker ``` （进行直接击杀本实体的实体）、 ``` target_entity ``` （交互行为中的目标实体）和 ``` interacting_entity ``` （交互行为的执行实体）。

### furnace_smelt

将物品转变为用熔炉烧炼后的对应物品。如果物品不可烧炼，则不做任何处理。

### limit_count

限制物品数量。

- - [图:整型][图:NBT复合标签/JSON对象]limit：限制物品的数量，物品数量会被钳制在此区间内。 - [图:整型][图:NBT复合标签/JSON对象]min：最小数量。 - - 数值提供器，见战利品表/数值提供器 - [图:整型][图:NBT复合标签/JSON对象]max：最大数量。 - - 数值提供器，见战利品表/数值提供器

### reference

### set_attributes

为物品加上属性修饰符。

- - [图:NBT列表/JSON数组]modifiers：属性修饰符列表。 - [图:NBT复合标签/JSON对象]：一个修饰符。 - [图:单精度浮点数][图:NBT复合标签/JSON对象]amount：指定修饰值。 - - 数值提供器，见战利品表/数值提供器 - [图:字符串]attribute：（命名空间ID）此修饰器修饰的属性。 - [图:字符串]id：（命名空间ID）修饰符的命名空间ID。 - [图:字符串]operation：修饰符的运算模式，可以为 ``` add_value ``` （增量操作，Op0）、 ``` add_multiplied_base ``` （倍率操作，Op1）和 ``` add_multiplied_total ``` （最终倍乘操作，Op2）。 - [图:字符串][图:NBT列表/JSON数组]slot：指定修饰符产生效果的槽位。值只能为 ``` mainhand ``` （主手）、 ``` offhand ``` （副手）、 ``` head ``` （头盔）、 ``` chest ``` （胸甲）、 ``` legs ``` （护腿）、 ``` feet ``` （靴子）、 ``` hand ``` （双手）、 ``` body ``` （身体）、 ``` armor ``` （所有盔甲）、 ``` any ``` （所有槽位）或 ``` saddle ``` （鞍）。当此项为列表时，列表内的字符串都为可以使修饰符产生效果的槽位。 - [图:布尔型]replace：（可选，默认为 ``` true ``` ）是否覆盖物品原有的属性修饰符。如果为false，则将列表内的属性修饰符附加到物品的属性修饰符列表中。

### set_damage

对可损坏的物品堆叠进行操作，输入一个耐久比然后转换为相应的耐久度。
```
当前耐久比=当前耐久度÷最大耐久度
```

。

- - [图:单精度浮点数][图:NBT复合标签/JSON对象]damage：输入的耐久比。 - - 数值提供器，见战利品表/数值提供器 - [图:布尔型]add：（可选，默认为false）是否将输入的耐久比视为增量。若为true，则最终设置的耐久度为 ``` ceil((输入的耐久比+当前耐久比)×最大耐久度) ``` ，否则为 ``` ceil(输入的耐久比×最大耐久度) ``` ，其中 ``` ceil ``` 表示向上取整。

注意，由于浮点数误差，在实际使用时可能需要偏移一个微小值，比如对于一个最大耐久度为10的可损坏物品，若要稳定减少耐久度1，输入的耐久比应设置为-0.10001。
