本条目所述内容仅适用于Java版。
维度类型（Dimension Type）控制了维度的环境光照、建筑高度等诸多行为。维度类型定义文件是维度类型在数据包中的数据驱动定义文件。

# 定义格式

维度类型在游戏内使用
```
DIMENSION_TYPE
```

注册表，数据包路径为
```
dimension_type
```

，即所有维度类型定义文件都需要在
```
data/<
命名空间
>/dimension_type
```

目录下定义，维度类型标签则需要在
```
data/<
命名空间
>/tags/dimension_type
```

目录下定义。

维度类型定义文件使用JSON格式，并具有下列结构：

- [图:NBT复合标签/JSON对象] JSON文件根对象 - [图:布尔型]has_fixed_time：（默认为 ``` false ``` ）维度是否逻辑上拥有昼夜更替。详见下文§ has_fixed_time。 - [图:布尔型]*has_skylight：维度是否具有天空光照，详见下文§ has_skylight。 - [图:布尔型]*has_ceiling：维度是否具有天花板，详见下文§ has_ceiling。 - [图:布尔型]*has_ender_dragon_fight：此维度是否可以启动末影龙战斗。 - [图:单精度浮点数]*ambient_light：维度的环境光照，用于生物生成行走目标值、着色器lightmap等计算。在原版着色器定义下此值应只在0至1之间取值。 - [图:双精度浮点数]*coordinate_scale：（0.00001≤值≤30000000.0）维度的坐标缩放值，影响下界传送门的传送和 ``` / execute in ... ``` 的行为。 - [图:字符串][图:NBT列表/JSON数组]*infiniburn：维度内火能在哪些方块上永久燃烧。可以为一个方块ID、一个方块标签的ID或一个方块ID的列表。 - [图:整型]*min_y：（-2032≤值≤2031，必须为16的倍数）维度可以存在方块的最低高度。因值必须为16的倍数，故此字段可用最大值为2016。 - [图:整型]*height：（16≤值≤2032 - [图:整型]*min_y，必须为16的倍数）维度可以存在方块的总高度。 - [图:整型]*logical_height：（0≤值≤[图:整型]*height）维度的逻辑高度，紫颂果的传送和游戏创建的下界传送门不会超过此高度。 - [图:整型]*monster_spawn_block_light_limit：（-0≤值≤15）怪物生成位置的最大方块光照。 - [图:整型][图:NBT复合标签/JSON对象]*monster_spawn_light_level：（-0≤值≤15）怪物生成位置的最大光照，使用内部天空光照计算，但雷暴时天空光照视为天空光照减10。若指定一个范围，则游戏每次尝试生成时都会采样一次。 - - 整数提供器，见Template:Nbt inherit/int provider/source - [图:NBT复合标签/JSON对象]attributes：维度的环境属性映射。如果有多个相同的环境属性，则游戏只使用最后一个值。 - [图:任意类型][图:NBT复合标签/JSON对象]<环境属性ID>：一项环境属性及其对应的值，详见环境属性。 - [图:字符串][图:NBT列表/JSON数组]timelines：维度活动的时间线。可以为时间线的ID、时间线的标签或一个时间线ID的列表。如果多个时间线对同一个环境属性的变化进行了定义，则游戏只使用最后一个时间线定义的环境属性。 - [图:字符串]skybox：（默认为 ``` overworld ``` ）维度的天空盒。取值可以为 ``` none ``` （无效果）、 ``` end ``` （每隔一段时间出现末地闪光，使用世界时钟时间计算）、 ``` overworld ``` （天空可以渲染太阳、月亮、星星等天体和日出日落效果）。 - [图:字符串]cardinal_light：（默认为 ``` default ``` ）维度的方块光照类型，取值可以为 ``` default ``` 和 ``` nether ``` 。与默认值相比， ``` nether ``` 会使[图:布尔型]shade为 ``` false ``` 的方块的顶面和底面亮度降低10%而不是0和50%，而流体和[图:布尔型]shade为 ``` true ``` 的方块的所有面的亮度降低10%，详见模型 § 模型元素。 - [图:字符串]default_clock：（命名空间ID）此维度所使用的世界时钟。不存在时在此维度不存在世界时钟。

# 定义行为

维度类型仅在服务端启动时加载一次，使用
```
/
reload
```

命令不可以使维度类型定义被重新加载，而必须重启服务端。

尽管游戏支持在数据包和
```
level.dat
```

中对维度类型内联定义，但游戏不支持加载内联维度类型的维度。

维度类型控制了维度内所有与世界生成无关的效果，包括建筑高度限制、环境效果和部分方块或生物的行为等。

## 维度行为

下列为维度类型里较复杂的维度效果，对应的游戏行为均假定已满足其他条件。其余不由维度类型控制的维度行为见§ 其他行为。

[图:布尔型]has_fixed_time控制了维度逻辑上是否拥有昼夜更替。注意：此值不控制太阳的东升西落、亮度的昼夜变化等视觉上的行为，它仅会使部分生物对昼夜更替的判定失效，例如：

- 玩家在任意游戏时间使用床时均会尝试入睡。（本质上是影响环境属性 ``` gameplay/bed_rule ``` 的 ``` when_dark ``` 条件）
- 溺尸始终保持敌对状态。
- 流浪商人不再饮用隐身药水或奶桶。
- 灾厄巡逻队始终可以尝试生成。
- 末影人始终不会增加随机传送的概率。
- 狐狸始终不会前往村庄或尝试睡觉。
- 僵尸围城始终可以尝试生成。
- 部分亡灵生物不会尝试躲避阳光。

[图:布尔型]has_skylight控制了下列行为：

- 是否存在天空光照。 - 同理影响阳光探测器的工作等。
- 是否可以生成幻翼。
- 是否拥有天气变化。

[图:布尔型]has_ceiling控制了下列行为：

- 初始动物生成寻找可生成方块时，其不会在对应的高度图选择方块，而是在对应高度图的高度上向下搜寻到首个上方为空气的非空气方块上选择方块。
- 玩家是否倾向于生成在Y=64上，而不是生成在最高的方块上。但如果世界是超平坦世界，依然会生成在最顶层。
- 影响部分地图更新行为。
- 是否不拥有天气变化。

## 其他行为

一些维度行为被游戏硬编码，无法被修改。

为便于描述，规定
```
overworld
```

维度为主世界维度，
```
the_nether
```

维度为下界维度，
```
the_end
```

维度为末地维度。游戏以它们的ID为判断依据。

- 玩家总是生成在主世界。
- 下界传送门在非下界维度时会尝试将实体按维度缩放传送到下界维度，如果世界不存在下界维度则什么也不做；在下界维度时会将实体按维度缩放传送到主世界维度。
- 末地传送门在非末地维度时会尝试将实体传送到末地维度，如果世界不存在末地维度则什么也不做；在末地维度时会将实体传送到主世界维度。
- 在末地维度的霜冰依赖方块光照而非内部天空光照融化。
- 末地维度永远不会拥有天气。
- 下界维度的地图的玩家图标会随机旋转。

# 内置维度类型

游戏本体内置了四种维度类型：

- ``` overworld ``` ：主世界。
- ``` the_nether ``` ：下界。
- ``` the_end ``` ：末地。
- ``` overworld_caves ``` ：主世界洞穴。未被直接使用，只用于先前创建的洞穴世界类型的世界。
