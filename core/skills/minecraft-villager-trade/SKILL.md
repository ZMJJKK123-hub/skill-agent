村民交易（Villager Trade）是村民和流浪商人生成实际交易选项时的交易蓝图。村民交易定义文件是村民交易在数据包中的数据驱动定义文件。

# 定义格式

村民交易在游戏内使用
```
VILLAGER_TRADE
```

注册表，数据包路径为
```
villager_trade
```

，即所有村民交易定义文件都需要在
```
data/<
命名空间
>/villager_trade
```

目录内定义，村民交易标签则需要在
```
data/<
命名空间
>/tags/villager_trade
```

目录内定义。

村民交易定义文件使用JSON格式，并具有下列结构：

- [图:NBT复合标签/JSON对象] JSON文件根对象 - [图:NBT复合标签/JSON对象]*wants：村民收购的第一个物品。 - [图:字符串]*id：（命名空间ID）收购的物品类型。 - [图:NBT复合标签/JSON对象]components：检查收购物品的数据组件。 - [图:任意类型]<数据组件ID>：一个组件的检查。 - [图:整型][图:单精度浮点数][图:NBT复合标签/JSON对象]count：（默认为1）收购的物品的基础数量，游戏最终将此值四舍五入取整计算。具体的收购价格见§ 收购价格。 - - 数值提供器，见战利品表/数值提供器 - [图:NBT复合标签/JSON对象]additional_wants：村民收购的第二个物品。 - 格式同[图:NBT复合标签/JSON对象]*wants。 - [图:字符串][图:NBT复合标签/JSON对象]*gives：村民出售的物品。 - - 物品模板，见Template:Nbt inherit/item template/source - [图:NBT复合标签/JSON对象][图:NBT列表/JSON数组]given_item_modifiers：对出售物品的额外修饰。如果最终物品堆叠为空，则此项交易选中后也不会生成交易选项。 - 见物品修饰器，不允许引用文件。 - [图:整型][图:单精度浮点数][图:NBT复合标签/JSON对象]max_uses：（默认为4，低于1时视为1）交易失效前的最大交易次数，游戏最终将此值四舍五入取整计算。 - - 数值提供器，见战利品表/数值提供器 - [图:整型][图:单精度浮点数][图:NBT复合标签/JSON对象]reputation_discount：（默认为0，低于0时视为0）交易的价格乘数。 - - 数值提供器，见战利品表/数值提供器 - [图:整型][图:单精度浮点数][图:NBT复合标签/JSON对象]xp：（默认为1，低于0时视为0）交易后给予的经验值，游戏最终将此值四舍五入取整计算。 - - 数值提供器，见战利品表/数值提供器 - [图:NBT复合标签/JSON对象][图:NBT列表/JSON数组]merchant_predicate：对村民的检查，如果谓词检测失败，则此项交易选中后也不会生成交易选项。 - 见战利品表谓词，不允许引用文件。 - [图:字符串][图:NBT列表/JSON数组]double_trade_price_enchantments：一个魔咒ID、魔咒ID的列表或一个魔咒标签，代表会使交易价格翻倍的魔咒。游戏会检查出售物品的 ``` stored_enchantments ``` 组件内是否拥有此处指定的魔咒，如果检查成功则使收购物品的额外数量翻倍。

村民交易的生成使用战利品上下文
```
villager_trade
```

，上述字段使用的参数如下：

- ``` this_entity ``` ：生成交易的村民。
- ``` origin ``` ：此村民脚部的位置。
- ``` additional_cost_component_allowed ```

# 定义行为

村民交易定义数据仅在服务端启动时被加载一次，使用
```
/
reload
```

命令不可以使村民交易定义被重新加载，而必须重启服务端。

村民交易定义了村民生成交易时实际使用的交易项目。其需要在交易集内引用，村民会根据交易集定义选择单项村民交易，并生成实际的交易选项。

## 收购价格

为保持随机性，村民收购的第一个物品的数量由基础数量和额外数量组成。基础数量由交易收购字段指定，额外数量由物品的
```
additional_trade_cost
```

组件指定。此组件只能由物品修饰器设置：

- ``` include_additional_cost_component ``` 为 ``` true ``` 时， ``` enchant_with_levels ``` 函数会根据附魔等级设置此组件，且在数值上和附魔用的等级相等。
- ``` include_additional_cost_component ``` 为 ``` true ``` 时， ``` enchant_randomly ``` 函数会根据魔咒的等级设置此组件，假定魔咒的等级为level，则设置的值为2+random(0,5+level⋅10)+3⋅level。

物品修饰完毕后，
```
additional_trade_cost
```

组件会被立刻移除，它的值将作为额外数量。如果物品符合价格翻倍的检查，则额外数量将翻倍。将最终的基础数量和额外数量相加，低于1时视为1，高于物品的最大堆叠数时视为最大堆叠数，作为生成交易时的收购数量。
